# OctoAcme — Role Onboarding Checklist

## Purpose
Help new team members get up to speed quickly and ensure consistent onboarding across all roles.

## General Onboarding (All Roles)
- [ ] Access provisioned: GitHub repository, project board, and communication channels (Slack/Teams)
- [ ] Read the [Project Management Overview](octoacme-project-management-overview.md)
- [ ] Review [Roles & Personas](octoacme-roles-and-personas.md) and understand your role's responsibilities and collaborations
- [ ] Meet with Project Manager to understand current project status, milestones, and risks
- [ ] Meet with Product Manager to understand product vision, roadmap, and success metrics
- [ ] Added to recurring team meetings (standups, sprint planning, reviews, retrospectives)
- [ ] Familiar with the [Execution & Tracking](octoacme-execution-and-tracking.md) workflows and team rhythms
- [ ] Familiar with the [Risk & Communication](octoacme-risks-and-communication.md) escalation paths
- [ ] Set up local development environment (if applicable)

---

## Role-Specific Onboarding Checklists

### Developer
- [ ] Repository cloned and local development environment running
- [ ] CI/CD pipeline understood; able to run tests and linting locally
- [ ] PR and branching conventions reviewed (see [Execution & Tracking](octoacme-execution-and-tracking.md))
- [ ] Introduced to codebase architecture and key modules
- [ ] First PR submitted and merged (e.g., a small bug fix or doc update)

### Product Manager
- [ ] Product roadmap and backlog reviewed
- [ ] Customer and stakeholder contacts identified
- [ ] Success metrics and KPI dashboards reviewed with Data Analyst
- [ ] Sprint planning and backlog refinement process understood

### Project Manager
- [ ] Project plan, milestones, and risk register reviewed
- [ ] Stakeholder communication plan established
- [ ] Status reporting cadence set up
- [ ] Escalation paths confirmed with team and sponsor

### UX Designer
- [ ] Design system and existing prototypes reviewed
- [ ] Access to design tools provisioned (Figma, etc.)
- [ ] Met with Product Managers and Developers to understand open design work
- [ ] User research findings and personas reviewed
- [ ] First design deliverable scoped and scheduled

### Technical Writer
- [ ] Existing documentation repository reviewed
- [ ] Documentation standards and templates familiarized
- [ ] Met with Developers and Product Managers to understand upcoming features requiring docs
- [ ] Documentation milestone dates added to the release calendar
- [ ] First documentation contribution submitted

### Security Engineer
- [ ] Security policies, standards, and runbooks reviewed
- [ ] Security scanning tools in CI/CD confirmed and understood
- [ ] On-call rotation and incident response procedures reviewed
- [ ] Threat model for current project reviewed or initiated
- [ ] Security review process communicated to Developers

### Operations Lead
- [ ] CI/CD pipeline and deployment automation reviewed
- [ ] Environment inventory (dev, staging, production) documented
- [ ] Monitoring and alerting dashboards reviewed
- [ ] On-call schedule and incident response runbook reviewed
- [ ] First deployment shadowed or led

### Support Specialist
- [ ] Support ticketing system access provisioned
- [ ] Existing FAQ and knowledge base reviewed
- [ ] Bug triage and escalation process understood
- [ ] Met with Product Managers and Developers for product context
- [ ] First support tickets triaged and resolved

### Data Analyst
- [ ] Access to analytics and data warehouse tools provisioned
- [ ] Existing KPI dashboards and definitions reviewed
- [ ] Met with Product Managers to align on key metrics and reporting needs
- [ ] Data pipeline and instrumentation architecture understood
- [ ] First analysis or dashboard update delivered
